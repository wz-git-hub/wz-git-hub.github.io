量化巡检发现 $9,763 凭证性虚构：链上对账修复与风控口径切换（2026-11-16）

发表于2026-11-16|更新于2026-11-17|故障排障
|阅读量:

风控净值锚定 $220.58，而不是账面 $9,983.88——这是今天最关键的判断。 巡检发现主网实盘进程仍在运行但无人下单，更严重的是账面权益与链上余额相差 45 倍。

一、五条策略线实况：活着但空转

策略线 账面 实际收益 笔数/胜负 状态
主网实盘（mainnet_smart_money） $9,983.88 -$15.32（-0.153%） 40 笔 / 13胜27负 活着，0 持仓，空转
主网链上钱包 av $221 / used 0 / free $221 — — 🔴 与账面不符
testnet（hl_smart_money.db） $13,155.20（+31.5%） 剔除对账补记后 -$0.14 187 笔有效 8 天无成交
paper 模拟盘（sim_account） $460.33（-53.97%） -$479.67，费 102.29 536 笔 / 24.1% 胜率 paused=1，停 62 天
影子做市 mm/grid 6 个库已移入 _archive/orphans_2026-09-30 无数据 — 已停 3.5 个月

结论是整栈进程仍在运行，但没人下单。主网链上钱包 av $221 与账面 $9,983.88 严重不符。testnet 剔除对账补记后实际收益为负，paper 模拟盘已停 62 天，影子做市库早已归档。

二、三方核对：不是漂移，是本金虚构

链上实际只有 $6.99 USDC（perp 为 0），但 trader 报告 av=$220.58。先查清这个 $221 是谁的数字。

核对项 数值 来源
链上真实入金 $220.794012（9.994 + 209.8 + 1.0 三笔） userNonFundingLedgerUpdates
链上 16 笔成交净额 -$0.212440（closedPnl -0.006 − fee 0.2064） userFills
恒等式验算 220.794012 − 0.212440 = 220.581572 对上 spot 余额 220.581655（差 0.00008）
账本 initial_usdc 10000.00 sm_account

根本问题不是漂移，而是账本本金从未与链上同步。 $9,763.30 差额是凭证性虚构，不是交易亏出来的。db.py 建表默认值 initial_usdc=10000.00 从未代表真实资金。

三、风控口径切换：故意不动日亏损熔断

改动方案的关键约束：日亏损熔断不能更换口径。若把 baseline 换成链上 $221，会立刻算出 97% 回撤并写入 halted=1，当天永久停开仓。只把 sizing 与敞口、保证金闸门切换到 min(账本, 链上 av)。

位置 改动 判别作用
_resolve_risk_equity()（新增） mainnet 取 min(账本, 链上av)；av 取不到 → 返回 None = fail-closed 账本 $9983 + 链上 $221 时，风控净值锚定 $220.58，不再按 $9983
check_portfolio_risk(risk_equity=) 闸门2 总敞口 / 闸门4 保证金 改用风控净值 同一笔 $400：旧口径 0.04x 放行 → 新口径 1.81x 拦截
闸门1 日亏损熔断 故意不动，仍用账本 equity 若换成 221，total_equity 从 9987 掉到 221 → 算出 97.8% 回撤 → 触发 3% 熔断并写 halted=1
_size_for_signal(chain_av=) cap 从「仅 withdrawable」扩到 min(withdrawable, av) unified 账户下 withdrawable 可能虚高，av 才是本账户净值

主网已确认生效：risk_equity=$220.58(src=mode_min)。同时发现一个覆盖漏洞：背离告警只在有信号时体检，无信号时会漏检。补到周期状态里。

四、展示层修复与 TTL 缓存快照模块

位置 改前 改后（实测值）
A 块主网指标 「账户权益 $9,983.88 · -0.16% vs 初始 $10,000」 「链上权益（真钱）$220.58 / 纸面账本 $9,983.88 / 凭证差额 $+9,763.30」+ 判定行「差额与登记基线一致，漂移 $0.00」
纸面权益算法 直接把 current_usdc 当权益（少算在仓名义） current_usdc + 未实现 + 在仓名义，与 daily_health 同口径
每日体检 只有账本口径 增 chain_av_usd / chain_source / chain_stale / chain_drift_usd / chain_verdict / paper_basis；链上变动 >$0.5 也计入"状态变化"；chain_verdict 为 crit 时进"需要关注"
页面取数 — 新增 chain_equity.py：TTL 300s 缓存 + 四级降级（live → 过期缓存 → 对账基线 → 不可用），从不抛异常，30 秒 rerun 不会打爆交易所接口

展示层确实把 initial_usdc=10000 当成真实本金在展示。准备做一个带 TTL 缓存的链上权益快照模块，供网页和日报共用，避免每个 30 秒的 rerun 都直接请求交易所接口。

五、yunpan_hub 虚惊：multiprocessing 父子对不是双开

关键发现：**E:\yunpan_hub 根本不是双开**。明细如下：

PID 角色 证据
27228 → 27224 server.py 父→子 父进程派生 multiprocessing 子进程，监听 8800 的只有子进程 27224（1 个端口 1 个持有者）
26344 → 26444 book_gate.py 父→子 同上，监听 8801 的只有 26444
18928 watchdog_window.py 仅 1 实例（pythonw 托盘）

之前判「双开」是数了相同命令行但没看父子关系——这两个是典型的 multiprocessing 父子对（子进程重跑同脚本所以 cmdline 一样），每个端口只有一个持有者，不需要也不应该杀。上一轮在 defi_dashboard 杀的那批是不同的：那批的父进程是两个不同的 watchdog.py，是真重复。

六、遗留与下一步

  1. 账本重建（sm_account 按链上重置） — 技术上不建议现在做：日亏损熔断故意保留账本口径，直接把 9983 改成 220 会让熔断算出 97% 回撤写 halted=1。差额登记为已知 offset，只监控差额自身的漂移。
  2. 背离告警覆盖漏洞 — 补到周期状态里，无信号时也体检。
  3. watchdog_mainnet.py 双开核实 ✅ — 完成，结论是虚惊，无动作。
